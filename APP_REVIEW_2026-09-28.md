## What the app does

Steady is a single-user fitness tracker at `fit.adeticket.com`. A Node 24 server stores profiles, check-ins, plans, workouts, food, activity, sleep, measurements, sessions and private images in SQLite on persistent single-instance App Service storage. The mobile web client supports first-run setup, daily check-in, deterministic workout planning with safety gates, live strength/cardio logging, History and trends, meal inventory and suggestions, CSV/print export, optional screenshot storage, reminders and a revocable public workout-sharing link. A separate date-only view runs at `fitdays.adeticket.com`. The production backup is off-site Blob Storage; its contents were not inspected in this review.

## Verified findings, in priority order

| ID / status | Impact and evidence | Proposed change; rough effort | Acceptance |
| --- | --- | --- | --- |
| F1 **Confirmed · P0** | **Today breaks after History during an active workout.** In a fresh synthetic account, save a strength set, open History, then return to Today. The page falls back to the older all-exercises layout; focused navigation, saved-set controls and finish review disappear. Browser console reports `TypeError: Cannot read properties of undefined (reading 'pattern')` at `public/app.js:65`. `wireToday()` globally selects `.exercise`, including hidden History articles, then indexes `state.plan.exercises[i]`. Reload restores the focused view. This interrupts a gym session and creates confusing save/finish behavior. | Scope workout queries to `#view-today` and use explicit exercise indices; guard missing plan items. Add a browser regression that switches Today → History → Today after saving sets. **Small, 2–4 h.** | No console error; the same active workout, set controls, rest timer and Review and finish remain usable after repeated navigation and refresh. Saved sets are unchanged. |
| F2 **Confirmed · P1** | **CSV labels cardio minutes as distance.** A synthetic treadmill entry saved as 15 minutes and 0.8 mi appears in `/api/export.csv` as a set row with value `15`, unit `mi`. The exporter writes duration but chooses `distanceUnit` as its unit (`server.js:278`). This can mislead anyone using the export. | Emit separate, explicitly named duration and distance fields/rows, with `min` for duration and `mi`/`km` for distance; keep old records exportable. **Small, 1–3 h.** | A 15-minute, 0.8-mile workout exports both quantities with correct labels and units; CSV tests cover missing distance and both unit systems. |
| F3 **Confirmed · P1** | **Distinct activity minutes vanish from the seven-day total when logged on a workout day.** `progress.js:activityTrend` chooses workout minutes *or* activity minutes for each day. A pure-function case with a 15-minute treadmill set and a separate 30-minute walk returned 15 minutes, not 45. A wearable summary could represent the same activity, so blindly summing everything would also be wrong. | Let users mark an activity as separate from or included in the saved workout; summarize distinct minutes while showing the basis. **Medium, 1–2 days**, including legacy-entry handling. | A separate 30-minute walk plus 15-minute treadmill session shows 45; a duplicate imported summary is counted once; sparse-day coverage stays correct. |
| F4 **Confirmed · P1** | **History measurement form has unnamed controls.** At 390px the accessibility tree exposes an unnamed measurement-type combobox and value spinbutton (`public/app.js:76`); daily-review unit selectors and diastolic field are also unnamed (`public/app.js:109`). This makes voice-control and screen-reader entry ambiguous. The screen has two separate CSV links to the same endpoint. | Add stable labels/fieldsets for kind, value, unit, systolic and diastolic; consolidate CSV action. **Small, 2–4 h.** | Every History form control has a unique accessible name, keyboard focus follows visual order, and one clearly named CSV action remains. |
| F5 **Confirmed · P2** | **The weekly review calls future days “unrecorded.”** On the first day of a new week it correctly says “1 of 1 elapsed days,” then says “Several days are unrecorded.” The note in `weekly-review.js` uses a fixed `<3` threshold without considering elapsed days. This can make a new week feel like a missed goal. | Base the note on elapsed days and data coverage; distinguish “week just started” from missing past entries. **Small, 1–2 h.** | Day one with its review saved does not warn about several unrecorded days; a later week with actual gaps does. |
| F6 **Confirmed UX · P2** | **Meal ideas are repetitive and occasionally awkward.** A new synthetic account saw chicken/oats/bananas for breakfast, chicken/root vegetables/oats for lunch and dinner, and banana/chicken as a snack. `meal-guidance.js:11` always picks the first eligible food per category from the alphabetized inventory. Suggestions are safe as general ideas but have little variety or preparation guidance. | Add deterministic rotation across available foods, simple preparation/portion examples and a “use another idea” choice. Keep allergy/restriction pause and avoid invented nutrition data. **Medium, 1–2 days.** | Across a week, available foods produce varied sensible combinations; allergies/restrictions still pause automatic ideas; suggestions never auto-log food. |
| F7 **Suspected test risk · P2** | Plain `npm test` failed on this Windows checkout when `fitness.test.js` imported `server.js`: `database is locked` at `PRAGMA journal_mode=WAL`. Running all tests with a unique temporary `DATA_DIR` and `--test-concurrency=1` passed **46/46**. The exact contribution of an existing local DB versus parallel test startup was not isolated. Tests currently allow `server.js` to open the default data path at import (`server.js:21–32`). | Give each server-importing test its own temp data directory before import; document a deterministic local test command. **Small, 2–4 h.** | Default test command passes repeatedly even when a separate local app is running; no test opens the developer's persistent data directory. |
| F8 **Suspected auth boundary · P1 investigation** | `security.js:googleIdentity` accepts Azure principal headers whenever `NODE_ENV=production` and `WEBSITE_SITE_NAME` are set. Code relies on Azure Easy Auth removing or replacing caller-supplied identity headers; this review did not test that ingress behavior. If that trust boundary were bypassed, single-user private records could be exposed. This is **not a confirmed production bypass**. | Review Azure Easy Auth forwarding settings and test a forged client-supplied principal at the public HTTPS edge using a non-owner synthetic account. Consider a trusted gateway boundary/integrity check if forwarding is not guaranteed. **Medium, 0.5–1 day investigation** before any code change. | Forged identity headers from an unauthenticated external client never create a local session or disclose `/api/me`; legitimate Google sign-in still works. |
| F9 **Suspected scale risk · P2** | `/api/me` returns up to 60 complete workout JSON records plus all foods/equipment profiles every time Today reloads (`server.js:174`), while `/api/progress` scans all measurements (`server.js:151`). Current synthetic data was fast; no large-history latency was measured. This may increase mobile loading as history grows. | Seed a representative, non-private 1–2-year fixture; measure response size, p95 API time and phone render time before adding pagination or summaries. **Small investigation, larger fix only if measured.** | Performance budget and measured baseline recorded; Today fetches only data it displays if the budget is exceeded. |

Existing private-session, safety, conflict, backup, chart, sharing and reminder tests contributed to the 46/46 isolated pass. This was not a penetration test or production account check.

## Product and workflow ideas

| ID / status | User benefit and evidence | Proposed change; effort / priority | Acceptance |
| --- | --- | --- | --- |
| I1 **New idea** | Faster gym use: Today includes food, sleep, activity, upload and plan in one long page. | Collapsible sections with the live workout and Save state prominent; **medium / P2**. | At phone width, a returning user reaches the next set in one tap; all tracking sections remain discoverable and keyboard accessible. |
| I2 **New idea** | Comparable load suggestions are unavailable until an equipment profile is created; the synthetic session defaulted to “Unlabelled equipment.” | Offer a quick equipment-name choice inside the active exercise and explain machine/per-hand load meaning; **medium / P2**. | User can label equipment during a session; history compares only the same exercise, equipment and unit. |
| I3 **New idea** | Daily food logging requires repeated typing even after favourite foods are seeded. | Quick-add recent food and saved meals, with an editable portion before saving; **small / P2**. | Common snack can be logged in two taps; no suggestion is logged merely by viewing it. |
| I4 **New idea** | The first-run card confirms routine but does not capture an optional step baseline or measurement goal. | Add optional baseline steps and preferred measurement cadence, without blocking tracking or imposing targets; **small / P2**. | Unknown baseline stays unknown; step targets are not escalated until enough real observations exist. |
| I5 **New idea** | History has charts and a weekly review but no concise reasoned “what changed this week” summary. | Add a factual weekly highlight based only on recorded workouts, recovery, steps and sparse-data coverage; **medium / P2**. | Highlight cites the underlying dates/counts, avoids calorie compensation and says when evidence is sparse. |
| I6 **New idea** | Date-only Fitdays and detailed History are separate; users may want a quick route between them. | Add a private in-app month calendar linking to a day review and a clearly identified public Fitdays link; **medium / P3**. | Calendar distinguishes planned rest, completed, active and missing dates without exposing private details on Fitdays. |
| I7 **New idea** | Export exists but the owner cannot select a date range or see a human-readable summary before downloading. | Add a date-range selector and export preview after F2 is fixed; **medium / P3**. | CSV/print include only the selected dates, correct units and no private screenshots by default. |
